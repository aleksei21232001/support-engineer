# Диагностика веб-сервера Nginx (Учебный проект)

## Цель
Отработать базовые навыки диагностики и управления сервисами в Linux, необходимые для роли Support Engineer.

## Что я сделал (пошагово)
Я выполнил эту практику в онлайн-терминале Ubuntu (Killercoda), чтобы безопасно отработать команды без настройки локального окружения.

1. **Установка:** Обновил пакеты и установил веб-сервер:
   `sudo apt update && sudo apt install nginx -y`
2. **Проверка статуса:** Убедился, что сервис работает:
   `sudo systemctl status nginx` (статус: active/running)
3. **Моделирование инцидента:** Остановил сервис, имитируя сбой:
   `sudo systemctl stop nginx`
4. **Диагностика через логи:** Проверил системный журнал, чтобы подтвердить состояние сервиса:
   `sudo journalctl -u nginx -n 10`
   *В логе увидел запись: "Stopped A high performance web server..."*
5. **Восстановление:** Запустил сервис обратно и проверил статус:
   `sudo systemctl start nginx` -> статус снова `active (running)`.

## Чему я научился
✅ Понимать, как управлять сервисами через `systemctl` (start, stop, status).
✅ Читать базовые системные логи через `journalctl` для диагностики состояния.
✅ Действовать по алгоритму: Проверка статуса → Анализ логов → Восстановление работы → Проверка результата.

## Почему это важно для Support Engineer
При обращении пользователя "ничего не работает", первая задача инженера — не гадать, а проверить статус сервиса и заглянуть в логи, чтобы понять, упал ли сервис, или проблема в чём-то другом (сеть, права доступа и т.д.).
