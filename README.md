## 📂 Что внутри

### 1. [Диагностика веб-сервера Nginx](nginx-diagnostic.md)
**Инструменты:** Linux (Ubuntu), `systemctl`, `journalctl`  
**Что сделал:** Установил веб-сервер, смоделировал сбой (остановка сервиса), проанализировал системные логи для выявления причины и восстановил работу сервиса.  
**Навык:** Базовая диагностика сервисов и чтение логов в Linux.

### 2. [Тестирование API через curl](api-tests.md)
**Инструменты:** Terminal, `curl`, JSON  
**Что сделал:** Выполнял HTTP-запросы (GET, POST) к тестовому API, анализировал статус-коды ответов (200 OK, 404 Not Found) и структуру JSON-данных.  
**Навык:** Понимание работы HTTP-протокола и диагностика проблем интеграций.

### 3. [SQL-запросы для диагностики данных](sql-queries.sql)
**Инструменты:** SQLiteOnline, SQL  
**Что сделал:** Создал тестовую базу данных (пользователи и заказы) и выполнил 5 практических запросов: поиск по фильтру (`WHERE`), сортировку (`ORDER BY`), анализ массовых сбоев (`GROUP BY`, `COUNT`) и поиск аномалий (`HAVING`).  
**Навык:** Самостоятельная проверка данных и гипотез в базе данных.

## 🎯 Моя цель на стажировке

Я понимаю, что работа Support Engineer — это не просто пересылка тикетов, а **инженерная диагностика**: 
1. Собрать факты и симптомы.
2. Проверить гипотезы (логи, сеть, база данных, API).
3. Либо решить проблему самостоятельно, либо передать разработчикам/админам **качественную эскалацию** с шагами воспроизведения и логами.

Эти учебные проекты — мой первый шаг к освоению этого подхода. Я быстро учусь, внимателен к деталям и готов применять эти знания на реальных задачах Т-Банка.
