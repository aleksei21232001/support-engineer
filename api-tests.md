# Тестирование API через curl (Учебный проект)

## Цель

Научиться работать с HTTP-запросами, понимать статус-коды и диагностировать проблемы API.

## Что я сделал

Я выполнил практику в онлайн-терминале Ubuntu (Killercoda), используя команду curl для работы с публичным тестовым API (JSONPlaceholder).

---

### 1. GET-запрос: получение данных

`curl https://jsonplaceholder.typicode.com/users/1`

**Результат:** получил JSON с данными пользователя (имя, email, телефон, адрес).

---

### 2. Проверка статус-кода ответа

`curl -I https://jsonplaceholder.typicode.com/users/1`

**Результат:** HTTP/1.1 200 OK — запрос успешен, сервер вернул данные.

**Что это значит:** статус-код 200 — стандартный ответ для успешного GET-запроса.

---

### 3. Ошибка 404: ресурс не найден

`curl -I https://jsonplaceholder.typicode.com/users/9999`

**Результат:** HTTP/1.1 404 Not Found — пользователь с ID=9999 не существует.

**Что это значит:** сервер корректно обработал запрос к несуществующему ресурсу и вернул ошибку 404.

---

### 4. POST-запрос: создание нового ресурса

`curl -X POST https://jsonplaceholder.typicode.com/users -H "Content-Type: application/json" -d '{"name": "Alexey", "email": "alexey@test.com"}'`

**Результат:** сервер вернул созданный объект с новым ID и моими данными.

**Что это значит:** метод POST используется для создания новых записей на сервере.

---

## Чему я научился

**HTTP-методы:**
- GET — получить данные с сервера
- POST — создать новые данные на сервере

**Статус-коды HTTP:**
- 200 OK — успешный запрос
- 404 Not Found — ресурс не найден
- 201 Created — ресурс успешно создан (для POST)
- 500 Internal Server Error — ошибка на стороне сервера

**Работа с curl:**
- Флаг -I — показать только заголовки (статус-код)
- Флаг -X POST — указать метод запроса
- Флаг -H — добавить заголовок (Content-Type)
- Флаг -d — передать данные в теле запроса

**JSON-формат:**
- Понимание структуры JSON-ответа
- Отправка данных в формате JSON

---

## Почему это важно для Support Engineer

При обращении пользователя "интеграция не работает" или "API возвращает ошибку", инженер поддержки должен:

1. Проверить endpoint (URL) — правильный ли адрес?
2. Посмотреть статус-код ответа — 200, 404, 500?
3. Проверить тело запроса и ответа — все ли данные корректны?
4. Понять, где проблема:
   - На стороне клиента (неверный запрос, 400 Bad Request)
   - На стороне сервера (ошибка в коде, 500 Internal Server Error)
   - В данных (ресурс не найден, 404 Not Found)

Эти навыки я отработал в данном проекте и готов применять их на реальных задачах.

## Полезные команды curl для диагностики

`curl -v https://api.example.com/data` — GET-запрос с подробным выводом

`curl -X POST https://api.example.com/users -H "Content-Type: application/json" -d '{"name": "Test"}'` — POST-запрос с JSON

`curl -o /dev/null -s -w "Time: %{time_total}s\n" https://api.example.com` — проверить время ответа

`curl -O https://example.com/file.txt` — скачать файл
